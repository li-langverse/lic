## Abstract

Swarm gap orchestration (registry ingest, backlog apply, handoffs) depends on read APIs that behave identically in homelab, K8s org-research Jobs, and CI. This pass audits api-coverage for the `swarm_coverage` meta-goal on 2026-06-11 and finds REST endpoints largely complete in `li-cursor-agents` when the ops-server runs, while MCP tooling, control-plane disk persistence, and PyYAML in the worker image leave orchestration blind spots that distort grading and block unattended gap refresh.

## Findings

### 1. Org-research Jobs lack REST parity

K8s researcher pods mount benchmarks + lic but typically **not** the ops-server. Meta-agents must use MCP or explicit file paths. Missing MCP read tools force brittle path knowledge — a coverage defect for `swarm_coverage`.

### 2. Control-plane persistence API gap

Without `state.json` and `latest-report.json`, the programmatic observer cannot expose `observer.retry_counts` or intervention history. Grade dimension `swarm_execution` reads as 100 (0 errors) while orchestration self-heal is **unobservable**.

### 3. Gap ingest CLI blocked on PyYAML

```
ModuleNotFoundError: No module named 'yaml'
swarm-gap-ingest: PyYAML required (pip install pyyaml)
```

Infra API contract failure: ingest dependency not declared in worker image. Apply artifacts can remain fresh while registry drift accumulates.

### 4. Orchestration signal drift

| Source | Top recommendations |
|--------|---------------------|
| Briefing heap | `ci_maintainer`, `security_auditor` |
| Scorecard | + `gap_explorer`, `plan_verifier` |

Without a unified API surfacing scorecard `recommended_agents` into briefing heap, gap orchestration agents starve despite 62 open registry rows.

### 5. Preflight API failures (non-SDK)

- `org_ci_audit` exit 1 — multiple repos return HTTP 404 (workspace clone gaps).
- `org_agent_kit_audit` exit 1 — `roadmap/agent-kit` not mounted.

These are read API failures for briefing consumers, not agent execution errors.
